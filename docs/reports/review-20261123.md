## 2 架构：值得先做的三件（互不阻塞）

1. **`E2+E4` 同一刀**：`one_split` 里 worker / tuner / flusher 三处手工 `abort` 换成自带 `Drop` 的
   `TaskGroup`；AIMD 闸门改成 `acquire() -> Permit`。理由：现在非 `RangeUnsupported` 的失败**只 abort 一半**，
   而 `JoinHandle::drop` 是 detach 不是 abort ⇒ 孤儿 worker 与下一代重试**同时写同一个 `.part`**。
2. **`C1+D1` 同一批**：`SizeHint` 三态 + 重试环保留 `last_err`。这两条互为因果：C1 制造病因，D1 把它丢掉。
3. **`A2`**：把"单 URL → `Job`"搬回 lib（`url_list::job_from_url`），让 `fetch` 与 `run` 真的共用一份，
   顺带消掉"`/dir/` 结尾 ⇒ 路径安全错误"这种误导性报错。

## 3 架构里**明确不建议**的

- **别按"重试 / 回退 / 进度"切 `one_split`**：这三段的价值在**先后顺序**（`download.rs:690-692` 写着"顺序不能换"），
  切成三个函数会让这个不变量从"眼前 12 行"变成"跨三个文件才能验证"。
- **别拆 `curseforge.rs`**：1056 行里 297 行是测试，剩下四层已经清楚；拆成"网络/纯"两半只会把
  `CfResolved`/`RealUrl` 变成跨模块类型，耦合一点没少。改判阈值写在报告正文里。
- **别开 `clippy::pedantic` 全量**：只挑 `unwrap_used`/`expect_used`/`panic_in_result_fn`/`allow_attributes_without_reason`。
  `let_underscore_must_use`、`cast_possible_truncation`、`must_use_candidate` 在本仓是噪音。
- **别开 `#![warn(missing_docs)]`**：144 个 `pub` item 里 60 个没文档，收益是"读起来舒服"，代价是一次 60 处大 diff。

## 4 依赖与 panic 面的实测数字（不是印象）

- `Cargo.lock`：240 个包，**0 个 git 源**，9 组重复大版本（`base64`/`getrandom`/`syn`/`windows-sys`/`toml_edit`…）。
  ⇒ `[sources] unknown-git = "deny"` 零成本，且能把铁律 1 变成机器判据；`multiple-versions` 用 warn 不用 deny。
- `unwrap/expect`：全仓 90/12。**按 `#[cfg(test)]` 切开后，生产路径只有 4 处**：
  `pathsafe.rs:50`（有 len 守卫）、`fabric.rs:111`（有 len 守卫）、`commands/run.rs:135`（跨模块不变量，该用类型表达）、
  `progress.rs:47`（全仓唯一把锁中毒当致命的点，与 `panic=unwind` 的决策不一致）。
- 顺带核实并**不予报告**的：`download.rs:715` 丢弃一次状态落盘（上界 2 秒，设计写明）、`--all-features` 无意义（无 features）、
  `tokio` 的 `full` feature 收窄（只省编译时间）。
