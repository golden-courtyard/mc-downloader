# 版本号与标签

这份文档规定：**什么时候跳版本、跳哪一位、标签长什么样**。目的只有一个 —— 让人看到 `0.6.0` 就知道
它相对 `0.5.0` 是什么性质的变化，而不是靠猜。

## 一、先把历史事实说清（"跳得随意"的来源）

| 版本 | 时间 | 出现在哪个提交 |
|---|---|---|
| `0.1.0` | 2026-10-21 | `b525541` 初版（vanilla + pack） |
| `0.5.0` | 2026-10-21 | `5f08c68` 工程配置收口 + 清 dead code |
| `0.6.0` | 2026-11-23 | `1b9540b` 源自备 + 文档体系这一批 |

**`0.2` / `0.3` / `0.4` 从来没有存在过** —— 从 `0.1.0` 一步跳到 `0.5.0`。而且在此之前**没有任何 tag**，
所以"0.5.0 里到底有什么"只能靠翻提交记录猜。这就是"随意"的具体形态：**不是数字大，是没有规则**。

**这次不改历史**：首个公开版本仍叫 `0.6.0`。理由——数字回退（改成 `0.1.0`）会让已有的 189 条提交、
CHANGELOG 与文档里所有 `0.6.0` 引用对不上，而它并没有错，只是没规则。**从这一版起有规则**，就够。

## 二、标签形态（与 dsh 一致）

```
mc-v0.6.0            # 正式版
mc-v0.7.0-alpha.1    # 预发布：alpha.N → rc.N → 正式
mc-v0.7.0-rc.2
```

- **名字**：`<包名简写>-v<semver>`。本仓库的包是 `mc-downloader`，简写取 `mc`（与 dsh 的 `dsh-v…` 同形）。
- **类型**：**轻量标签**（`git tag mc-v0.6.0`，不带 `-a`）。dsh 的 44 个 tag 都是 `commit` 类型；
  附注信息写在发布提交里，不重复存一份。
- **一致性**：标签里的版本号**必须**等于 `Cargo.toml` 的 `version`。改一处忘另一处 = 发布物无法追溯。
- **每个 tag 对应一个 `release(mc): x.y.z` 提交**：该提交只做三件事 —— 改 `Cargo.toml`、刷新 `Cargo.lock`、
  把 CHANGELOG 的 `[Unreleased]` 收成版本节。

## 三、跳哪一位（0.x 阶段）

| 变化 | 跳哪 | 例 |
|---|---|---|
| **破坏性**：用户必须改配置或改脚本 | **minor** | 0.6.0（`[source]` 六项变必填、脚本要 `schema`） |
| **只加功能，不动既有用法** | **minor** | 0.7.0（若只新增子命令/参数） |
| **只修 bug** | **patch** | 0.6.1 |
| 预发布迭代 | 在目标版本后加 `-alpha.N` / `-rc.N` | 0.7.0-rc.2 |

三条硬规矩：

1. **不许跳号**。下一个 minor 就是当前 +1（`0.6` → `0.7`），不跨 `0.8`、不"凑个整齐的数"。
2. **同一个 minor 内可以有多轮 alpha / rc**，但不许为了发一个预发布而改 minor。
3. **0.x 阶段"破坏性也走 minor"是刻意的**：SemVer 在 0.x 允许这样，而且它比"每次破坏都跳 1.0"诚实 ——
   1.0 应该意味着承诺，不是"破坏得够多了"。

## 四、什么时候才配 1.0

四条同时满足才行，缺一条就继续 0.x：

- [ ] **配置与脚本格式稳定**：连续两个 minor 没有破坏性变更（即 `[source]`、`schema = 1` 这类契约不再动）；
- [ ] **关键路径有真机验证记录**：原版 / Fabric / Forge / NeoForge 各自的"装完能启动"都有人验过
      （README 的验证状态表里不许有"结构对但没启动过"当通过）；
- [ ] **已知缺口都处理或明确不修**：issue 里没有"我们知道但不打算修"的隐身项；
- [ ] **有人依赖它**：至少一个外部使用者在真实场景用过一个版本周期（否则 1.0 只是自我感觉）。

## 五、发布流程里对应哪几步

见 [release.md](release.md)。与本文件相关的三步：

1. CHANGELOG 的 `[Unreleased]` → `[x.y.z] - YYYY-MM-DD`（只改标题，内容不洗）；
2. `Cargo.toml` 改 `version`、`cargo build` 刷新 `Cargo.lock`（diff 应只有本包那一行）；
3. `git tag mc-vx.y.z && git push origin mc-vx.y.z`，**tag 与 `Cargo.toml` 必须一致**。
