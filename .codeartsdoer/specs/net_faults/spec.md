# spec — net_faults（网络故障与跨平台语义验证）

> 2026-10-21 ｜ 状态：draft ｜ 范围由 lmq 拍板：**L2 / L2′ / Linux 平台语义**
> 上游依据：`DESIGN.md` §11（当前验证能力矩阵）· 本对话中「测试层次 × 执行环境」结论

---

## 1. 组件定位

### 1.1 核心职责

在受控网络下验证下载器对「慢 / 断 / 丢包 / 乱序」与 Linux 文件系统语义的行为。
（32 字）

### 1.2 核心输入

| 输入 | 来源 | 形态 |
|---|---|---|
| 被测二进制 | `cargo build` | 本机或 VM 内的 `mc-downloader` |
| 故障场景定义 | 本文档 §5 + `scripts/net_faults/scenarios/` | 可执行脚本，一条场景一个 |
| 假源数据 | 本地生成 | 固定尺寸、**非均匀内容**（`bytes(i%251)`）的文件 |
| 预期判据 | 场景定义内联 | `PASS` / `FAIL` 文本 + 退出码 |

### 1.3 核心输出

| 输出 | 形态 | 判据 |
|---|---|---|
| 单场景结论 | stdout 一行 `PASS <场景名> <关键指标>` | 退出码 0 |
| 失败证据 | 日志尾部 + `.part` / `.part.state` 快照 | 可定位到「哪一层、哪个机制」 |
| 汇总报告 | `report.md`，一场景一行的表 | 覆盖 §5 全部场景 |

### 1.4 职责边界（**明确不做什么**）

| 不做 | 归谁 |
|---|---|
| 安全渗透：中间人、TLS 拦截、信任链篡改 | 未立项（`DESIGN §8.2` 已记两个信任链缺口）|
| 协议模糊：畸形响应、错误长度、200 冒充 206 | L1 假源，另立 feature |
| 录制重放（L3）、生产混沌（L4） | 不做 |
| Windows 特有语义（UAC 重定向、文件占用） | Windows VM，另立 feature |
| 性能基准（吞吐量对标 IDM/aria2） | 不做 |

## 2. 领域术语

| 术语 | 定义（本 feature 内） |
|---|---|
| **L2 故障** | 传输层可观测的异常：带宽受限、延迟、抖动、连接被 RST |
| **L2′ 故障** | 内核/链路层异常：丢包、乱序、重复包 |
| **假源** | 本地 HTTP 源，支持 Range(206)，内容固定可控 |
| **平台语义** | 文件系统与 OS 行为差异：大小写敏感、稀疏文件、删除打开中的文件等 |
| **可信结论** | 同一场景连跑 3 次结论一致；单次结论不算 |

## 3. 角色与边界

### 3.1 核心角色

| 角色 | 职责 |
|---|---|
| **验证执行者** | 在目标环境跑场景脚本，收集结论 |
| **被测程序** | `mc-downloader`，仅通过 CLI 使用，**不修改其内部**（唯一授权例外见 §5.4 注）|
| **假源** | 单一职责：按 Range 请求返回字节，不模拟故障 |

### 3.2 外部系统

| 系统 | 提供什么 | 不可用时的退路 |
|---|---|---|
| **Kali VM** | `tc netem`、`iptables`、root | L2/L2′ 全部阻塞，仅平台语义可做 |
| **GitHub Actions (ubuntu-latest)** | Linux 用户态、无 root | 只做平台语义，不能做 L2/L2′ |

### 3.3 交互上下文

```
[假源 127.0.0.1:PORT]  ←──HTTP──  [mc-downloader]
        ↑
   tc netem / iptables        ← 故障施加于此，**不修改假源与被测程序**
```

**关键约束**：故障**只施加在网络层**，不改假源、不改被测程序。
理由：一旦为了造故障去改被测程序，测的就不是生产代码了。

## 4. DFX 约束

| 维度 | 指标 | 可测方式 |
|---|---|---|
| **4.1 性能** | 单条 L2/L2′ 场景 ≤ 120s；AIMD 场景 ≤ 300s | 脚本内 `timeout` 兜底 |
| **4.2 可靠性** | 同一场景连跑 3 次，`PASS/FAIL` 结论必须一致 | 脚本 `--repeat 3` |
| **4.3 安全性** | 全部流量走 `127.0.0.1`；**禁止访问公网** | `netstat` 核对连接对端；脚本内 `iptables -A OUTPUT ! -d 127.0.0.1 -j REJECT` 可选 |
| **4.4 可维护性** | 新增一条场景 = 新建一个脚本文件，**不改框架** | 目录约定即接口 |
| **4.5 兼容性** | 平台语义测试在 CI Ubuntu 自动跑；L2/L2′ **不进 CI**（需 root） | CI 里 `#[cfg(target_os = "linux")]` 分流 |

## 5. 核心能力

### 5.1 L2 传输层故障

#### 5.1.1 业务规则

**带宽一律用 bit 制**，与 `tc netem rate` 的参数一致 —— 避免 `MB/s` 与 `mbit` 混写
（差 8 倍，且会让「实测 vs 目标」的判据整体反向）。

- **必须**覆盖下列 **4 个 `rate` 档位**，含区间两端：

  | 档位（netem 参数）| 等价 | 意图 |
  |---|---|---|
  | `800kbit` | 100 KB/s | 下限：测超时与重试边界 |
  | `8mbit` | 1 MB/s | 典型慢速 |
  | `80mbit` | 10 MB/s | 典型宽带 |
  | `400mbit` | 50 MB/s | 上限：测高带宽下的并发效率 |

- **必须**覆盖 **2 个 `delay` 档位**：`20ms±5ms`（城域）· `200ms±50ms`（跨洋）
- **必须**覆盖 **1 条**中途 RST
- **必须**在施加故障的**同一条链路上**保持假源可达（即故障只影响被测端到源）

> **场景总数以本节与 5.2.1 的表格为准**：4 + 2 + 1 + 3 + 2 + 1 + 1(AIMD) = **14 条**。
> 任何文档引用这个数字，必须与本节逐个对得上；不得自行计数。

#### 5.1.2 交互流程

```
1. 起假源 → 生成固定 sha1 的测试文件
2. tc qdisc add dev <IF> root netem <参数>
3. 跑 mc-downloader fetch（--size 已知，走分片路径）
4. 收尾：比对落盘 sha1；tc qdisc del
5. 输出 PASS/FAIL + 实测速率
```

#### 5.1.3 验收条件

| 触发场景 | 预期行为 |
|---|---|
| `rate 1mbit` 下下载 16MB | When 完成，the 工具 shall 落盘内容 sha1 与源一致 |
| `rate 1mbit` 下实测吞吐 | the 实测吞吐 shall 落在 `[0.8×, 1.2×] × 限速值` |
| `delay 200ms` 下下载 16MB | When 完成，the 工具 shall 报告的总耗时 ≥ 200ms × 分片数 ÷ 并发数 |
| 下载到 50% 时注入 RST | If 连接被重置，the 工具 shall 在重试预算内恢复并完成，**或** 明确报错退出且 `.part.state` 记录已完成分片 |
| 下载到 50% 时注入 RST 后**进程不被杀** | While 进程存活，the 工具 shall 重试该分片，且**不得**整进程退出。（实现上用指数退避；本 feature **不**为其设机械判据 —— 要证明退避间隔递增需日志时间戳，成本高于收益，故降为描述性） |

### 5.2 L2′ 内核层故障

#### 5.2.1 业务规则

- **必须**覆盖 **3 个 `loss` 档位**：`1%` · `5%` · `20%`
- **必须**覆盖 **2 个 `reorder` 档位**：`10%` · `25%`
- **应当**覆盖 **1 个 `duplicate`**：`10%`
- **禁止**在乱序/重复场景下放松 sha1 校验（校验是这组场景的判据本身）
- **必须**在乱序/重复场景使用 **128MB** 测试文件（见 §6.2）——
  分片数不足时偏移错位类缺陷不显现，场景会「PASS 但结论无效」

#### 5.2.2 验收条件

| 触发场景 | 预期行为 |
|---|---|
| `loss 5%` 下下载 16MB | When 完成，the 落盘内容 shall 与源 sha1 一致（TCP 重传兜底）|
| `loss 20%` 下下载 16MB | If 超时耗尽，the 工具 shall 报错且**不留**可被误认为"可续传"的 `.part.state` |
| `reorder 25%` 下分片下载 | When 完成，the 分片偏移写入 shall 不错位（sha1 一致即证明）|
| `duplicate 10%` 下下载 | When 完成，the 落盘 shall 与源一致（重复包由 TCP 去重，**若不一致说明我们自己的偏移算错了**）|

### 5.3 Linux 平台语义

#### 5.3.1 业务规则

- **必须**在 CI 的 Ubuntu 上自动执行，**不需要 root**
- **必须**覆盖：大小写敏感、稀疏文件、`rename` 覆盖语义、打开中的文件能否删除、fd 上限
- **禁止**用 mock 替代真实文件系统调用（这条的判据就是真实行为）

#### 5.3.2 验收条件

| 触发场景 | 预期行为 |
|---|---|
| 目标路径 `assets/A` 与 `assets/a` 同时存在 | the 工具 shall 视为**两个不同文件**（Linux 大小写敏感），不得合并 |
| 对 1GB 文件 `set_len` 后立刻查磁盘占用 | the 占用 shall ≈ 0（稀疏文件生效）；**若文件系统不支持稀疏，脚本 shall 明确报「本环境不支持」而非静默通过** |
| `.part` 存在时 `rename` 覆盖同名成品 | the `rename` shall 原子成功（POSIX 语义）|
| 打开中的 `.part` 尝试删除 | the 删除 shall 成功（Linux 允许），且不残留句柄泄漏 |
| `--concurrency 64` 下的 fd 消耗 | When 以 `--concurrency 64` 跑一次**真实下载**，the **mc-downloader 进程** shall 不因 `EMFILE` 失败；若失败，shall 在错误信息中点明 fd 上限。（**禁止**用「探测本机 fd 上限」替代 —— 那测的是环境属性，与"工具在并发下是否健壮"没有因果关系）|

### 5.4 时变带宽（AIMD）

- **必须**能按时间阶跃改变带宽（**bit 制，与 §5.1.1 档位同源**）：
  `80mbit → 8mbit → 80mbit`，**每段 ≥ 20s**
- **必须**同时记录：每秒实测吞吐、`--adaptive` 的 worker/semaphore 变化
  （需新增最小观测点，见 **`design §1.3 D6`**）
- 这是 `--adaptive` **唯一**的验证途径（`DESIGN §8.2` 长期挂着）

#### 验收条件

| 触发场景 | 预期行为 |
|---|---|
| 带宽由 `80mbit` 阶跃降至 `8mbit` | When 持续 ≥ 20s，the 吞吐 shall 收敛到新带宽的 `[0.8×, 1.2×]` |
| 带宽由 `8mbit` 阶跃升至 `80mbit` | When 持续 ≥ 20s，the 吞吐 shall **上升**（证明 tuner 会加 permits）|
| 对照：`--adaptive` 关闭 | the 吞吐 shall 不高于 `piece_conns × 新带宽`（未干预基线）|

> **唯一授权例外（覆盖 §3.1「不修改其内部」）**：为观测 AIMD 内部状态，
> 允许在 `download.rs` 增加**只输出、不改任何状态、无环境变量时零行为差异**的诊断语句，
> 精确边界见 `design §1.3 D6`。**除此之外任何生产代码改动都超出本 spec 授权范围。**

### 5.5 结果判定与报告

- **必须**每条场景独立可执行：`bash scripts/net_faults/scenarios/<name>.sh`
- **必须**输出机器可解析的一行 `PASS/FAIL <name> <k=v ...>`
- **禁止**出现「有动作无断言」的场景（做了但没法判 PASS/FAIL 不算场景）

## 6. 数据约束

### 6.1 场景定义

| 字段 | 必填 | 约束 |
|---|---|---|
| `name` | 是 | `[a-z0-9_]`，与文件名一致 |
| `layer` | 是 | `l2` / `l2p`（Linux 平台语义由 Rust 测试承载，不走脚本元数据，故不设此值）|
| `needs_root` | 是 | 决定能否进 CI |
| `timeout_s` | 是 | ≤ 300 |
| `assert` | 是 | 至少一条可机械判定 |

### 6.2 测试数据

- **必须**非均匀内容（`bytes(i % 251)`）：均匀内容无法检出写偏移错误
- 尺寸固定三档：`16MB`（L2/L2′ 主用）、`128MB`（乱序/重复用）、`1GB`（稀疏文件用，可不落满）
- **必须**用**离线预算**的 sha1 常量：对 `bytes(i%251)` 的生成规则，用独立脚本一次算出并写进场景文件
- **禁止**在运行时由 `fakeorigin.py` 现算后再与下载结果比对 ——
  现算会掩盖「生成端本身就写错」：一个内容错误的文件与基于它算出的 sha1 **自洽通过**，
  两侧同错，测不出任何东西

## 7. 未落地即失效的调查结论（**本 feature 不含，但必须留痕**）

2026-10-21 调查发现、`DESIGN §8.2` 已记但尚未修的两处**信任链校验缺口**：

| 缺口 | 官方数据 | 我们的结构 |
|---|---|---|
| version JSON 无校验 | manifest 每个版本带 `sha1` | `manifest::Ver` 只有 id/url/type |
| assetIndex 无校验 | 带 `sha1` + `size` | `version::AssetIndex` 只有 url/id |

修法各 3–4 行，判为「功能修正」而非新功能。**本 feature 不处理**，避免范围蔓延。
