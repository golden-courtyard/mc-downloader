# AIMD 那条证明，人话版

`proofs/Proofs/Aimd.lean` 里的 `climb_closed` 读起来像一串"洗牌指令"，因为它只写**动作**，
不写**每一步的目标长什么样**。这篇把同一个证明拆成手算 + 逐行对照。

## 一、要证的是什么

结论一句话：**一轮锯齿里，平均并发是峰值的 75%**。

### 先手算一个例子（峰值 16）

砍半到 8，然后每 tick +1 爬回 16：

```
tick:   1   2   3   4   5   6   7   8   9
并发:   8   9  10  11  12  13  14  15  16
```

- 平均 = (8+9+…+16) / 9 = 108 / 9 = **12**
- 12 / 16 = **0.75**

这就是"锯齿自己吃掉 25%"的全部内容。没有黑魔法。

### 再一般化

令峰值 = 2m（例子里 m = 8）。那么一轮的取值是：

```
m, m+1, m+2, ..., 2m        （共 m+1 个数）
```

记它们的和为 `S(m)`。要证的是：

```
2 · S(m) = 3 · m · (m+1)
```

为什么这个式子等价于"平均 75%"？两边同除以 2(m+1)：

```
S(m)/(m+1) = 3m/2            ← 平均
3m/2 ÷ 2m   = 3/4            ← 占峰值的比例
```

## 二、递推式是怎么冒出来的

Lean 里的定义没写"求和"，写的是递推：

```lean
def climb : Nat → Nat
  | 0      => 0
  | m + 1  => climb m + (3 * m + 3)
```

从 `m` 走到 `m+1` 时，序列从 `m … 2m` 变成 `m+1 … 2m+2`，变化有两部分：

| 变化 | 增了多少 |
|---|---|
| 原有 `m+1` 个数各 +1 | `+ (m+1)` |
| 末尾新增一个数 `2m+2` | `+ (2m+2)` |
| **合计** | `3m + 3` |

所以 `S(m+1) = S(m) + 3m + 3`。这一步是纯算术，和 Lean 无关。

## 三、归纳：两步，都是初中代数

**第一步（m = 0）**：序列只有 `0` 一个数，`S(0) = 0`。右边 `3·0·1 = 0`。成立。

**第二步（假设 m 成立，证 m+1）**：

```
2·S(m+1) = 2·(S(m) + 3m+3)          ← 用递推式
         = 2·S(m) + 6m + 6           ← 展开
         = 3m(m+1) + 6m + 6          ← 用归纳假设 2·S(m) = 3m(m+1)
         = 3m² + 3m + 6m + 6
         = 3m² + 9m + 6
```

再看要证的右边：

```
3(m+1)(m+2) = 3(m² + 3m + 2) = 3m² + 9m + 6      ← 一样
```

证完。**全部内容就这三行代数**。

## 四、Lean 的每一行对应哪一步

| Lean 代码 | 对应手算的哪一步 |
|---|---|
| `induction m with` | 拆分 `m = 0` 与 `m+1` 两种情形 |
| `| zero => decide` | 第一步：`0 = 0`，直接判定 |
| `simp only [climb]` | 用递推式把 `S(m+1)` 换成 `S(m) + 3m+3` |
| `rw [Nat.mul_add, ih]` | ① 把 `2·(A + B)` 拆成 `2A + 2B`；② 把 `2·S(m)` 换成归纳假设 `3m(m+1)` |
| `simp only [Nat.mul_add, Nat.add_mul, Nat.mul_comm, Nat.mul_left_comm]` | 两边都展开成单项式之和（`Nat.mul_add` 是分配律，另两条是交换律） |
| `omega` | 收尾：此时两边都是 `3m² + 9m + 6` 的形状，线性算术判定器闭合 |

## 五、为什么读起来像天书

三个原因，都不是数学难：

1. **Lean 只记录动作，不记录状态**。`rw [Nat.mul_add, ih]` 之后目标长什么样，文件里看不到 ——
   要在编辑器里逐步执行才有 `goal` 显示。**读 Lean 证明的正确方式是看目标状态，不是读文本**。
2. **代数被拆成了原子**。人一眼看出 `3m²+9m+6 = 3(m+1)(m+2)`，Lean 要你先把两边都整理成
   "同一种形状"，它才好比较 —— 所以有四条重写引理。
3. **核心库没有 `ring`**。有 `ring` 的话这行可以直接写成 `ring`，但 `ring` 在 Mathlib 里
   （见 `PROOF.md`），所以只能用分配律 + `omega` 手工凑。

## 六、这个证明**没有**说什么

- 它证的是**理想化模型**：每 tick +1、砍半后立刻开始爬、没有噪声、每轮都爬回峰值；
- 它**没有**证真实网络下的锯齿形状 —— 噪声会让周期变短、幅度变小，实际平均可能低于 75%；
- 它**没有**证"75% 是可接受的代价" —— 那是产品判断（默认并发上限那一节讨论的事）。
